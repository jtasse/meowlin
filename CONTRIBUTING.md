# Contributing to Meowlin

This project is a serverless AWS demo application. It should stay practical, low-cost, and easy to explain in a portfolio, blog post, or video.

The primary contributor currently uses AI coding assistants in VS Code, so this file includes guidance for both human contributors and coding assistants.

## Project Priorities

Prioritize work in this order:

1. Get small vertical slices working end-to-end.
2. Keep architecture realistic but not overbuilt.
3. Prefer clear AWS fundamentals over framework magic.
4. Keep costs low.
5. Preserve a path from mocks to real implementation later.

Avoid large rewrites unless they clearly simplify the project.

## Current MVP Scope

The current MVP is not a full app. It is a backend/serverless demo.

In scope:

- API Gateway HTTP API
- Lambda
- DynamoDB
- S3 presigned uploads
- Postman as a stand-in client
- SQS and a processing Lambda
- Mocked classification results

Out of scope for now:

- Mobile app
- Real machine learning
- Real cat breed recognition
- User authentication
- History page
- CI/CD
- Multi-environment deployment

## Coding Assistant Instructions

When helping with this repo:

- Make incremental changes.
- Explain why a change is needed before making sweeping changes.
- Do not overengineer.
- Do not introduce new frameworks unless explicitly requested.
- Preserve working behavior before refactoring.
- Prefer explicit, readable code over clever abstractions.
- Keep examples copy/paste friendly.
- Use PowerShell-friendly commands unless Bash is specifically requested.
- When editing YAML, be careful with indentation and validate with SAM.
- If changing SAM infrastructure, explain the CloudFormation/SAM impact.
- Avoid vague placeholder names like `MyFunction`, `handler1`, or `testTable`.

## Language Guidance

- Use Node.js for API-style Lambda functions.

```text
RequestUploadUrlFunction
GetClipFunction
ListClipsFunction
```

Use CommonJS in current Node Lambda files unless the project is intentionally converted to ES modules.

CommonJS pattern:

```js
const crypto = require("crypto")

exports.handler = async (event) => {
	// handler body
}
```

Avoid mixing CommonJS and ES module syntax in the same Lambda. Do not use `import` or `export` in `.js` files unless `package.json` has:

```json
{
	"type": "module"
}
```

Use Python later for the processing/classification Lambda if desired:

```text
ProcessClipFunction
mockClassifier
```

This is because Python is a natural fit for mocked or future audio/ML-style logic.

## DynamoDB Guidance

Current table:

```text
MeowlinClips
```

Current primary key:

```text
clipId : String
```

Do not add ordinary item fields to DynamoDB `AttributeDefinitions`. In CloudFormation/SAM, `AttributeDefinitions` should include only table keys and index keys.

Minimum item fields:

```text
clipId
clientClipId
clipStatus
createdAt
s3Key
```

`clipId` is generated by Lambda using a UUID and is the source of truth. `clientClipId` is client-generated and used for correlation/debugging.

Use conditional writes when creating items:

```js
ConditionExpression: "attribute_not_exists(clipId)"
```

## S3 Upload Guidance

Do not upload audio through API Gateway or Lambda.

Correct flow:

```text
Client -> RequestUploadUrl Lambda -> presigned S3 PUT URL -> Client uploads directly to S3
```

The Lambda should return:

```text
clipId
clientClipId
clipStatus
s3Key
uploadUrl
uploadUrlExpiresInSeconds
```

Use short-lived presigned URLs, such as 900 seconds.

S3 lifecycle (see `template.yaml`): objects under `uploads/` expire after 7 days by default (`UploadObjectExpirationDays`). Incomplete multipart uploads under that prefix abort after 1 day.

Upload limits (`POST /uploads`):

- `contentType` must be an allowed audio MIME type (explicit list plus any `audio/*` prefix).
- `fileSize` (bytes) is required and must match the bytes sent in the subsequent presigned `PUT`.
- Default max size is 10 MiB (`MaxUploadSizeBytes` in `template.yaml`).
- `fileName` sets the object extension in S3 (`uploads/{clipId}/{clientClipId}.{ext}`); any audio extension is allowed.
- API Gateway throttling and a regional WAF per-IP rate limit apply to `POST /uploads` (see `template.yaml` parameters `ApiUploadThrottle*` and `WafUploadsRateLimitPerIp`).
- CORS allowlist: set `CorsAllowedOrigins` at deploy time (S3, API Lambdas). Include every UI origin (local + GitHub Pages).

## SAM Guidance

Use SAM as the infrastructure source of truth.

Environment/stage policy for this repository:

- Treat the root `template.yaml` as canonical; do not edit generated files in `.aws-sam/build/`.
- `dev` and `prod` API stages currently provide URL/workflow separation only.
- Do not describe current stages as fully isolated environments unless resources are split by stack/account.
- Keep local testing defaulted to `dev`; explicitly opt into `prod` when needed.
- Keep separate Postman environments for dev and prod base URLs.

Common commands:

```powershell
sam validate
sam build
sam local start-api
sam deploy
```

Start local API:

```powershell
sam local start-api
```

`sam local start-api` exposes the Lambda at the root: `http://127.0.0.1:3000/uploads`. To test with explicit stage paths locally, use `sam local start-api --stage dev` or `sam local start-api --stage prod`. Postman can use `{{base_url}}/{{stage_name}}/uploads` which works for both local and deployed APIs.

If local API testing behaves unexpectedly, stop and restart `sam local start-api` after rebuilding.

If CloudFormation fails, inspect stack events:

```powershell
aws cloudformation describe-stack-events `
  --stack-name meowlin `
  --query "StackEvents[?ResourceStatus=='CREATE_FAILED' || ResourceStatus=='UPDATE_FAILED'].[Timestamp,LogicalResourceId,ResourceType,ResourceStatusReason]" `
  --output table
```

Do not add `ReservedConcurrentExecutions` unless Lambda account concurrency quota is high enough. The current account has shown a concurrency limit of 10, which prevents reserving concurrency while maintaining AWS's required unreserved capacity.

## Postman Guidance

Postman is the temporary client.

### Rules for editing Postman files

Only edit files that were originally created by Postman's Git Sync. Do not create new collection files from scratch or convert exported JSON into this format manually.

### Recommended requests

1. `POST /uploads`
2. `PUT {{uploadUrl}}` with binary audio file (size must match `fileSize` from step 1)
3. Future: `GET /clips/{{clipId}}`

In the `POST /uploads` Tests tab, capture values:

```js
const response = pm.response.json()

pm.environment.set("clipId", response.clipId)
pm.environment.set("clientClipId", response.clientClipId)
pm.environment.set("s3Key", response.s3Key)
pm.environment.set("uploadUrl", response.uploadUrl)

pm.test("Request Upload succeeded", function () {
	pm.response.to.have.status(200)
	pm.expect(response.clipId).to.exist
	pm.expect(response.clientClipId).to.exist
	pm.expect(response.s3Key).to.exist
	pm.expect(response.uploadUrl).to.exist
})
```

The S3 upload request should use:

```text
Method: PUT
URL: {{uploadUrl}}
Headers:
  Content-Type: audio/mpeg
Body:
  binary audio file
```

Do not send JSON or form-data for the actual S3 upload.
